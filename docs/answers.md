# Ответы к защите

1. Loopback внутри контейнера принадлежит его network namespace; DNAT направляет соединение на сетевой интерфейс контейнера, где слушателя нет. Нужно слушать 0.0.0.0 внутри, а на хосте публиковать только 127.0.0.1. Эти адреса относятся к разным пространствам имён.
2. Удалённый из последнего коммита пароль остаётся в истории и считается скомпрометированным. Его нужно заменить в работающей системе. Историю можно очистить согласованным переписыванием и удалением доступных копий/кэшей, но ротацию это не заменяет. В нашем восстановленном main лишь нерабочая заглушка; настоящий пароль сгенерирован отдельно.
3. RUN rm скрывает файл в верхнем слое, но прежний слой хранит его содержимое. Пользователь, скачавший образ из реестра, может извлечь слой. Секрет надо исключить из контекста до сборки.
4. Exec CMD запускает Gunicorn непосредственно PID 1, позволяя доставлять SIGTERM при docker stop. Проверка: docker exec <container> ps -o pid,comm либо docker top; shell-форма добавляет оболочку и может задержать остановку до SIGKILL.
5. ${REDIS_PASSWORD} раскрывает Compose на хосте при чтении конфигурации (окружение оболочки приоритетнее .env). $$ экранирует доллар для Compose; $REDIS_PASSWORD раскрывает оболочка внутри healthcheck из окружения контейнера. Без $$ пароль подставится раньше и окажется в описании проверки. Экспорт другого пароля в хостовой сессии может рассогласовать requirepass и env_file.
6. Официальный entrypoint распознаёт redis-server и понижает привилегии до redis. sh -c обходит эту ветвь; процесс может остаться root. Проверить docker top с полями user,pid,comm; полный аргумент команды не выводить, он содержит пароль.
7. Redis доступен другим контейнерам общей сети и администратору хоста. Пароль ограничивает обращения при ошибочном подключении к сети/скомпрометированном соседнем приложении; отсутствие публикации не заменяет аутентификацию.
8. Простой depends_on задаёт порядок запуска процессов, service_healthy ждёт успешного PING. Без готовности первые запросы приложения могут дать 500 из-за отказа Redis. Это не автоматическая обработка последующих отказов хранилища.
9. down сохраняет именованный том; down -v удаляет данные. latest может сменить основную версию и формат/совместимость данных. redis:7-alpine ограничивает основную версию; AOF по умолчанию синхронизируется раз в секунду, при аварии возможна потеря последней секунды.
10. Старый сертификат содержит SAN devops.local и не подтверждает kv.devops.local; нужен отдельный SAN. Старый --cacert не доверяет новому самоподписанному сертификату: ошибка проверки. Nginx выбирает TLS server и сертификат по SNI; без подходящего имени использует default server.
11. client:192.168.56.1 — Host-only адрес Windows, принятый Nginx и установленный в X-Real-IP. TCP peer приложения — прокси/bridge, поэтому адрес исходного браузера так не получить. Клиент может подделать X-Forwarded-For; доверять можно лишь цепочке заголовков от настроенных доверенных прокси. Прямой доступ приложения закрыт.
12. systemd запускает SSH, Nginx, Docker и UFW с сохранёнными настройками; restart:unless-stopped запускает контейнеры, не остановленные вручную. Ранее вручную остановленные контейнеры сами не стартуют. Named volumes сохраняются; Redis AOF и PostgreSQL используют свои тома. Перезапуск гостя не требует перезагрузки Windows.
13. hosts Windows нужен браузеру для разрешения домена в IP. Nginx принимает IP-соединение и выбирает server по SNI/Host; upstream задан IP 127.0.0.1 и не требует DNS имени kv.devops.local на сервере.
14. Docker DNAT/FORWARD обходит обычные входящие INPUT-правила UFW. Раздел [5] проверяет только 5000/5432 и пропустит ошибку 8004. В [6] добавлена проверка compose port app 8004 == 127.0.0.1:8004; отрицательный опыт подтвердил exit 1, восстановление — exit 0.

# Объяснение результатов

Встроенный DNS пользовательской сети backend разрешает redis в адрес контейнера. Приложение читает REDIS_HOST=redis, не привязывается к изменяемому IP. /whoami подтверждает все требуемые заголовки прокси. Секрет хранится в серверном .env с правами 600 и исключён из Git/контекста; пароль в окружении и аргументах Docker доступен администраторам Docker, поэтому полный inspect и compose config не включены в снимки. Поля процессов показаны без аргументов именно для защиты секрета.

Ревизия и app.py относятся к восстановленному учебному примеру. Для подтверждения неизменности исходного приложения преподавателя и дефектов именно его шаблона требуется получить оригинальный kr2-template. Устная защита и внесение неисправности преподавателем выполняются студентом лично; сохранённый отказ является тренировкой.
